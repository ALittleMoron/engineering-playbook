# User Interface Feedback

When changing a user action, make success, failure, and blocked states understandable. Show the
outcome or the next corrective step through appropriate inline feedback, notification, loading or
disabled state, or focus change; do not silently ignore an invalid or skipped action.

Preserve accessible names and discernible states for controls, including icon-only controls.
Check the relevant loading, error, empty, and populated states and use the established interface
patterns of the product.
